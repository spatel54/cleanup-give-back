# Admin dashboard UX audit — 2026-07-22

**Persona:** Admin — sole program admin; laptop + iPad; job is clear session reviews, protect court-hour deadlines, then occasional ops (orders, events, feedback).  
**Method:** Review against PRD §7.2 + goals G1–G5; scan of operational dashboard patterns (action-first admin UX, Stripe/Linear progressive disclosure, work-queue tables).  
**Surface:** `admin/` home (`DashboardWorkbench`).

## Research takeaways applied

| Principle | Source pattern | Admin implication |
|-----------|----------------|-------------------|
| Next action in ~10s | Role-based ops dashboards | Lead with “what’s waiting” + one **Review next** CTA |
| Action > decoration | Admin UX 2026 / table-first tools | Charts and maps are optional; queue is the work |
| KPI → evidence | Stripe / ops dashboards | Keep KPI cards linked, but **after** the queue |
| Progressive disclosure | Linear / Stripe | Collapse neighborhood map + charts behind Show |
| Calm hierarchy | Stripe type scale | “Today” briefing strip, then amber queue only |
| Bulk on tables | Moderation / CBO work queues | Select + **Approve selected** |
| Mobile decisions | iPad-first PRD | Sticky **Review next** above bottom nav |

## Findings → changes

| # | Finding (the admin's pain) | Change shipped |
|---|------------------------|----------------|
| 1 | “Dashboard” + KPI row stole first attention from the queue | Rename page to **Today**; **TodayFocus** strip with count + primary CTA |
| 2 | Queue lacked urgency / duration / court clarity | Waiting-age labels, duration, **Court** chip, **Review** action |
| 3 | No bulk path for obvious approvals | Select all / row checkboxes + **Approve selected** |
| 4 | Heatmap competed with daily ops | Collapsed under **Neighborhood map · optional** |
| 5 | Recent feed duplicated queue rows | Default recent feed **skips** items still in queue |
| 6 | Court risk cards looked neutral | Behind vs due-soon color; days left / overdue |
| 7 | Keyboard power-user tip was noisy on the page | Tip moved under queue; full shortcuts stay in drawer |
| 8 | Mobile lost the primary CTA while scrolling | Sticky **Review next** bar above bottom nav |

## Intentional non-changes

- Mock banner stays (honesty > polish while fixtures are on).
- Period toggle kept (hours/KPIs still period-scoped).
- Donuts remain available under Charts — Admin needs them for board updates, not every morning.

## Follow-up (2026-07-22) — Bento simplification

Dashboard rebuilt as a **bento grid** to cut clutter:

| Tile | Role |
|------|------|
| Review (2×2) | Hero work surface — Start + Approve/Review rows |
| Waiting / Approved / Hours / Feedback | One-metric tiles → deep links |
| Court hours | Deadline list |
| Jump to | Common destinations |
| Insights (collapsed) | All charts + map in one place |

Removed from the default surface: TodayFocus strip, bulk select, recent activity feed, sticky mobile CTA, separate map/charts disclosures.

## Follow-up (2026-07-27) — Insights promoted, not hidden

Feedback from real usage: a fully collapsed Insights drawer meant composition signals (approval rate, trend direction) were never seen day-to-day. Replaced the collapsed disclosure with:

| Tile | Role |
|------|------|
| Snapshot (new, always visible) | Approval rate, top activity, approved-hours sparkline — one glance, no click |
| Waiting / Approved / Hours / Feedback | Approved + Hours now carry an inline sparkline (`Sparkline`, no chart library) |
| Insights (new dedicated page, `/insights`) | Full trend area, how-long-sessions-wait/decisions bars, court progress, composition donuts, neighborhood map — linked from Snapshot, Jump to, and the nav sidebar |

Queue rows, Court hours rows, and Sessions rows now link to a real per-volunteer profile (`/volunteers/[id]`, keyed by Supabase Auth user id) instead of dead-ending at the drawer.

## Follow-up (2026-07-27) — Recent decisions replaces Jump to; session deep-links; court badge

The **Jump to / Common work** tile duplicated the sidebar nav and surfaced nothing new. Replaced it:

| Tile | Role |
|------|------|
| Recent decisions (replaces Jump to) | Last approved/declined sessions this period — volunteer, activity, status chip, court marker; each row opens the full session |

Session deep-links (`/sessions/[id]`) now work everywhere a session row appears — Today's Review queue and Recent decisions, the Sessions list (table + mobile cards, **including mock preview**), and `ReviewDrawer` (**Open full session →**). `sessions/[id]` falls back to `MOCK_SESSIONS` fixtures (read-only info + local-only Approve/Decline via `MockSessionActions`) when a live row isn't found, so mock ids like `m3` no longer 404.

**Court-ordered marker fixed:** the `COURT` label reused the same amber (`#835400`/`#ffddb5`) as `StatusChip`'s `under_review`, so a court-ordered session waiting in the queue read as a second, confusing warning. Added `CourtBadge` (`admin/components/ui/CourtBadge.tsx`) — cool slate (`#243447` on `#e8eef5`) — and swapped it in everywhere a session/queue row shows a court marker: Today queue + Recent decisions, Sessions list (table badge + mobile card, replacing the amber ⚖️ circle), `ReviewDrawer`'s Type stat, and session detail headers (live + mock). `StatusChip`'s amber stays exclusive to Under Review/queue urgency and Court Hours deadline risk ("Behind"/"Soon") — those are a different signal (deadline urgency, not session type) and are unchanged.

## Follow-up (2026-07-27) — Deep-links stay live-safe without the service-role key

The session/volunteer deep-links above only degrade to mock **at the data layer** (empty tables). Two render paths still assumed `SUPABASE_SERVICE_ROLE_KEY` was present and would crash a real row instead of degrading: `sessions/[id]`'s live branch and `volunteers/[id]`. Both now use `tryCreateServiceClient()` like the rest of the admin (Sessions list, Court Hours, Today, Volunteers list) — real names/photos appear automatically once the key is added to `admin/.env.local`; until then they show a short explanatory message instead of a 500. Sessions list inline Approve/Decline also gained the same try/catch + toast pattern as Today's queue actions, so a write failure surfaces as a toast, not a crash.
